# 프로젝트 스크린샷 캡처 — 로컬 에이전트용 지시서

이 저장소가 도는 원격 컨테이너는 이그레스 정책이 `*.vercel.app` 을 막는다
(CONNECT 403, 실측). 그래서 데모 스크린샷은 **네트워크가 열린 로컬에서** 찍어야 한다.

아래 프롬프트를 브라우저를 쓸 수 있는 로컬 에이전트에게 그대로 주면 된다.

---

## 소유자가 할 일

1. 이 저장소를 로컬에 클론하고 브랜치를 받는다.
2. `npm ci && npx playwright install chromium`
3. 아래 프롬프트를 에이전트에게 준다.
4. 에이전트가 끝내면 `public/shots/` 를 커밋·푸시한다.

---

## 에이전트에게 줄 프롬프트

> 이 저장소의 포트폴리오 사이트에 올릴 **프로젝트 데모 스크린샷**을 찍어 줘.
> 사이트 자체를 찍는 게 아니라, 사이트가 소개할 **다른 프로젝트 세 개**를 찍는 거야.
>
> 먼저 `scripts/shots.config.json` 과 `scripts/capture-shots.mjs` 를 읽어. 설정에 적힌
> 경로는 **출발점이지 정답이 아니야.** 실제로 열어 보고 더 좋은 화면으로 고쳐.
>
> ### 대상
>
> | 프로젝트 | 어디 | 상태 |
> |---|---|---|
> | FestiFriends | https://ff-frontend-rust.vercel.app/ | 배포됨 |
> | Pookjayo | https://pookjayo.vercel.app/ | 배포됨 |
> | YORR | 배포 URL 없음 | 미러 저장소를 클론해서 로컬로 띄워야 함 |
>
> YORR 은 https://github.com/jadewisemann/yorr 의 `frontend` 를 클론해서 개발 서버로
> 띄운 뒤 `baseUrl` 을 `http://localhost:<포트>` 로 채워. 실시간 멀티플레이라 화면
> 하나를 보려면 방을 만들어야 할 수도 있어. 백엔드 없이 안 되면 **안 된다고 보고해.**
> 억지로 빈 화면을 찍지 마.
>
> ### 몇 장, 어떤 걸
>
> 프로젝트당 **3~4장**, 데스크톱과 모바일을 섞어서.
>
> - YORR — 모바일 위주 (휴대폰이 컨트롤러인 게임 플랫폼)
> - FestiFriends — 데스크톱·모바일 반반
> - Pookjayo — 모바일 위주 (모바일 우선 제품)
>
> **무엇을 고르는가가 이 작업의 핵심이야.** 랜딩 페이지 하나만 네 번 찍지 마.
> 고르는 기준은 하나다 — **그 화면을 보면 이 제품이 무엇을 하는 물건인지 알 수 있는가.**
> 목록·검색 결과·상세·예약 흐름처럼 실제 콘텐츠가 채워진 화면이 좋고, 빈 상태·로딩
> 스켈레톤·로그인 폼은 나쁘다. 모달이나 토스트가 떠 있으면 닫고 찍어.
>
> 로그인이 필요하면 시도해 봐. 계정이 없어서 못 들어가면 **로그인 벽이라고 보고해.**
> 회원가입을 새로 하지는 마.
>
> ### 찍는 법
>
> ```bash
> node scripts/capture-shots.mjs --dry-run   # 계획 확인
> node scripts/capture-shots.mjs             # 전체
> node scripts/capture-shots.mjs pookjayo    # 하나만
> ```
>
> 스크립트가 `public/shots/<프로젝트>/<kind>-<이름>.png` 로 저장하고
> `public/shots/capture-report.json` 에 결과를 남겨. 이미 축소 모션·`document.fonts.ready`
> 대기·HTTP 상태 확인·**거의 빈 화면 탐지**가 들어 있어. 「의심」으로 표시된 건 반드시
> 파일을 직접 열어서 확인해.
>
> 원본 해상도로 저장돼야 해. 3D 평면에 텍스처로 올라가서 기울기 때문에, 미리 줄인
> 이미지는 뭉개져. 스크립트가 `deviceScaleFactor` 2~3 으로 찍으니 건드리지 마.
>
> ### 넣기 전에 지울 것 — 이 저장소는 공개다
>
> `docs/portfolio/CONTENT.md` §9 가 텍스트에서 금지하는 것은 스크린샷 안에서도 금지야.
> 찍힌 화면에 아래가 보이면 그 화면은 쓰지 말거나, 그 부분을 **잘라내.**
>
> - 팀원 실명 · 프로필 사진 · 이메일 · 전화번호
> - 실제 사용자 데이터, 결제 정보, 토큰이 들어간 URL
> - 소속 기관 내부 용어
>
> **블러는 쓰지 마.** `DESIGN_SYSTEM.md` §2 가 금지하고 기계 검사가 잡아. 그리고 블러는
> 되돌릴 수 있어서 가린 게 아니야. 잘라내거나 불투명하게 덮어.
>
> ### 끝나면 보고할 것
>
> 1. 프로젝트별로 몇 장 찍었고 각각 어떤 화면인지
> 2. 못 찍은 것과 그 이유 (로그인 벽 · 배포 없음 · 백엔드 필요 · 빈 상태밖에 없음)
> 3. 가린 게 있으면 무엇을 왜 가렸는지
> 4. `public/shots/capture-report.json` 에서 「의심」으로 뜬 항목을 어떻게 처리했는지
>
> 못 찍은 걸 못 찍었다고 말하는 게 억지로 채우는 것보다 훨씬 쓸모 있어. 사이트 쪽에서는
> 장수가 모자라면 배치를 바꾸면 되지만, 빈 화면이 섞여 들어오면 그걸 모르고 배치한다.

## 돌아온 뒤

`public/shots/` 에 이미지가 들어오면 사이트 쪽에서 할 일:

1. `src/components/showcase/shots.ts` 매니페스트를 실제 파일·크기로 채운다.
2. `CONTENT.md` §8 의 「프로젝트 이미지 · 영상: 없음」 행을 갱신한다. 그 행이
   「이미지 없는 시각 전략이 필요하다」의 근거였고, 이제 근거가 사라진다.
3. 실제 이미지로 다시 캡처해서 배치를 판정한다. 플레이스홀더로 맞춘 구도는
   실제 스크린샷의 밀도·색과 다르므로 **반드시 다시 본다.**
