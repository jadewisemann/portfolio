# Motion Language

확정: 2026-08-31 · MOTION_SYSTEM 노드 · 아트 디렉션: `ART_DIRECTION.md` (이음선)

**속성 하나에 소유자는 하나다.** 두 시스템이 같은 인라인 스타일에 값을 쓰면 마지막에 쓴
쪽이 이기고, 그것은 테스트가 아니라 눈으로만 보인다. 그래서 소유권을 문서로 정하고
게이트로 강제한다 (§12).

## 1. 라이브러리

### 1.1 채택

| 시스템 | 소유 범위 |
|---|---|
| **Motion** (`motion` v13) | 레이아웃 전이 · 공유 요소 · 진입 1회 |
| **CSS** | 상태 · 대비 · 두께의 미세 전이 |
| **IntersectionObserver** | 불리언 상태만 만든다. 보간하지 않는다 |

### 1.2 GSAP 삭제

GSAP 을 쓰지 않는다. `package.json` 에도 없다.

사유: **스크롤 오프셋의 함수인 시각 속성이 0개다** (§5.1). 스크럽 · 핀 · 대형 타임라인이
없으므로 GSAP 의 소비자가 존재하지 않는다. 라이브러리를 두고 쓰지 않는 것보다 없는 것이
정직하다. 되살리려면 이 문서의 §5.1 을 먼저 뒤집어야 한다.

### 1.3 Lenis 삭제

스크롤 이송을 가로채지 않는다. 사유: 관성 스크롤은 소유할 수 없는 지속 시간을 만들고,
접근성 도구(스크린리더 커서 · 키보드 페이지 이동)와 싸운다. 브라우저 기본 스크롤을 쓴다.

### 1.4 Three.js

이 사이트에 3D 씬이 없다. 도입하지 않는다.

## 2. 스스로 시작하는 애니메이션 금지

사용자 행동(로드 · 포커스 · 클릭 · 호버 · 뷰포트 진입) 없이 시작하거나, 시작한 뒤
스스로 반복하는 애니메이션을 **0개**로 유지한다.

- `@keyframes` · `animation-name` · `animation:` 을 쓰지 않는다 (기계 검사).
- 카운트업 · 타이핑 · 무한 빔 · 셔머 · 그라디언트 순환은 전부 반려다
  (`COMPONENT_REGISTRY.md` C3 · C4 · C5).
- 예외 하나: 히어로 진입 (§9). 로드 이벤트이고 문서 수명 동안 1회다.

## 3. 이징 — 세 개

| 토큰 | 곡선 | 쓰임 |
|---|---|---|
| `--ease-settle` | `cubic-bezier(0.2, 0, 0, 1)` | **1차.** 무언가가 제자리에 앉을 때 |
| `--ease-travel` | `cubic-bezier(0.4, 0, 0.2, 1)` | **2차.** 무언가가 다른 자리로 이동할 때 |
| `--ease-spine` | `cubic-bezier(0.16, 1, 0.3, 1)` | **3차.** 장면 간 대역 전용 — 척추의 재배치 |

`--ease-spine` 신설 사유 (2026-08-31, GOLDEN_FIX 1): 장면 간 대역(§4)에서
`--ease-travel` 은 700ms 이상에서 미끄러져 보이고 `--ease-settle` 은 끝이 죽는다.
대역이 셋이면 이징도 셋이어야 한다. **네 번째 이징은 추가하지 않는다.**

스프링을 쓰지 않는다 — 지속 시간이 확정되지 않으면 축소 모션 대체와 E2E 대기 조건을
쓸 수 없다.

## 4. 시간 — 단일 상한이 아니라 위계

**개정 (2026-08-31, GOLDEN_FIX 1, 디렉터 결정).** 이전 규칙은 "320ms 를 넘는 전이를
만들지 않는다"였다. 그 단일 상한을 폐기한다.

폐기 사유: 단일 상한은 **대비를 구조적으로 불가능하게 만든다.** 어떤 전환은 숨을 쉬어야
하고 어떤 장면은 거의 정지해야 하며, 침묵이 스펙터클을 강하게 만든다. 모든 전이가 같은
대역에 있으면 위계가 없고, 위계가 없는 모션은 저작된 것이 아니라 덧붙여진 것으로 읽힌다.
GOLDEN_REVIEW 1 에서 motionCoherence 5.8 로 미달한 원인의 절반이 이것이다.

상한 대신 **대역**을 정한다. 모든 전이는 정확히 한 대역에 속한다.

| 대역 | 범위 | 무엇 | 이징 |
|---|---|---|---|
| 즉각 (input) | ≤ 120ms | 입력 응답 · 잉크 농도 · 밑줄 두께 · 활성 상태 | `--ease-settle` |
| 장면 내 (intra) | 200 ~ 420ms | 같은 절 안의 자리 이동 · 펼침 | `--ease-travel` |
| 장면 간 (inter) | 420 ~ 900ms | 척추의 재배치 · 장면 전환 | `--ease-spine` |
| 정지 (hold) | ≥ 200ms | 값이 도착한 뒤 아무것도 시작하지 않는 구간 | — |

| 토큰 | 값 | 대역 |
|---|---|---|
| `--duration-contrast` | 90ms | 즉각 |
| `--duration-state` | 120ms | 즉각 |
| `--duration-sort` | 320ms | 장면 내 |
| `--duration-spine` | 620ms | 장면 간 |
| `--duration-hold` | 200ms | 정지 |

규칙:

- **500ms 를 넘는 전이는 장면 간 대역에서만 허용한다.** 그 밖에서 500ms 는 금지다 —
  금지되는 것은 느림 자체가 아니라 **무구분한 느림**이다.
- 스태거는 같은 대역 안에서만 겹친다. 항목당 최대 60ms, 총 스태거 240ms 상한.
  스태거가 대역을 넘어가면 두 대역이 섞여 위계가 사라진다.
- 장면 간 전환이 진행 중일 때 새 장면 간 전환을 시작하지 않는다. 큐에 쌓지 않고
  **최신 값이 이긴다** (스크롤을 빠르게 내리면 중간 절을 건너뛴다 — 이것이 맞다).
- 장면 간 전환이 끝난 뒤 최소 `--duration-hold` 동안 아무것도 시작하지 않는다.
- 히어로 진입은 장면 내 대역에 속한다 (§9).

## 5. 스크롤

### 5.1 스크롤 응답 — 연속은 없다, 이산은 있다

**개정 (2026-08-31, GOLDEN_FIX 1, 디렉터 결정).** 이전 규칙은 "스크롤 위치의 함수인
시각 속성은 0개다"였고, 그 결과 사이트 전체에서 움직이는 것이 2개였다. 그것으로는
저작된 스크롤을 만들 수 없다.

새 원칙:

> **스크롤 오프셋의 연속 함수인 시각 속성은 계속 0개다.
> 그러나 절의 진입은 참값 사이의 이산 전환을 촉발할 수 있다.**

허용:

- IntersectionObserver 가 "지금 어느 절인가"라는 **이산 상태**를 만든다 (§5.2).
- 그 상태 변화가 이음선 척추의 위치를 **한 참값에서 다음 참값으로** 옮긴다.
  지속 시간은 우리가 소유한다 (장면 간 대역, §4).
- 정지 상태에서 척추는 **항상 그 절의 실측 비율 위에 있다.**

계속 금지:

- `useScroll` · `useTransform` · `scrollYProgress` (기계 검사 유지).
- 스크롤 위치에 비례하는 `opacity` · `translate` · `scale` · 색.
- 패럴랙스 · 핀 · 뷰포트 진입 시 절 페이드인.
- 스크롤 이송 가로채기 (Lenis 계속 삭제, §1.3).

**왜 이것이 원래 논거를 지키는가.** 원래 논거는 "스크롤로 움직이면 값이 연출로
강등된다"였다. 강등의 원인은 움직임이 아니라 **임의의 중간값이 화면에 상주하는 것**이다.
스크럽은 스크롤 위치를 곧 값으로 만들어 거짓 정밀도를 생산한다 — 화면의 44% 가 어떤
실측값도 아닌 상태가 오래 지속된다. 이산 전환은 모든 정지점이 참값이므로 거짓 정밀도가
없다. 중간 프레임은 값이 아니라 **값의 변화**이고, 그 변화(이전 → 이후)가 이 사이트의
주제 그 자체다.

### 5.2 IntersectionObserver 의 허용 범위

- 콜백은 **불리언 하나**를 준다 ("현재 절이 어느 것인가"). 스타일을 쓰지 않는다.
- 보간은 CSS 가 한다.
- **768px 미만에서는 관찰자를 만들지 않는다** — 모바일에 sticky 레일이 없으므로
  관찰할 이유가 없다.

### 5.3 `scroll-behavior` 금지

앵커 이동은 브라우저 기본 동작에 맡긴다. `scroll-behavior: smooth` 는 소유할 수 없는
지속 시간이므로 §3 · §4 의 규칙 밖에 있다. 착지 위치는 `scroll-margin-top: 56px` 로 잡는다.
`overscroll-behavior` 는 가로 스크롤 컨테이너에 **필요한** 속성이므로 이 금지에 걸리지 않는다.

## 7. 블러 언어

없다. `filter: blur` · `backdrop-filter` 금지 (기계 검사). 초점 이동을 흐림으로 표현하지
않는다 — 대비로 표현한다.

## 8. 스케일 · 회전 언어

- `scale()` · `rotate()` · `skew()` 를 애니메이션하지 않는다. 이것은 **문서 규칙**이고
  기계 검사에서 뺐다 — 정적 SVG 의 `transform` 속성과 주석에서 오탐이 잦다
  (오탐이 잦은 게이트는 곧 무력화된다).
- 허용되는 애니메이션 속성 전체 목록: `opacity` · `translate`(레이아웃 전이가 계산한 것) ·
  `color` · `background-color` · `text-decoration-thickness` · `border-width` · `height`.
- 앱 소스에서 `requestAnimationFrame` 을 쓰지 않는다 (문서 규칙).

## 9. 타이포그래피 모션 — 사이트 전체에서 하나

히어로 두 줄의 진입뿐이다.

- 소유자: **Motion 단독.** 줄당 340ms, 둘째 줄 지연 60ms.
- `translateY 14px` = 28px 리듬의 절반. 줄이 자기 행 상자 안에서 올라와 괘선에 앉는다.
- **글자 단위로 쪼개지 않는다.** 줄 단위다 — 한글에서 글자 단위 분해는
  `word-break: keep-all` 과 싸우고 어절을 깨뜨린다 (`COMPONENT_REGISTRY.md` C6).
- 억제 규칙:
  - 축소 모션에서 최종 상태를 즉시 렌더하고 초기 상태를 거치지 않는다.
  - 언어 토글 · 테마 변경에서 재생하지 않는다. 문서 수명 동안 1회 (모듈 스코프 래치).
  - IntersectionObserver 에 걸지 않는다. 로드 이벤트이고 스크롤 이벤트가 아니다.

### 9.1 JS 없이도 읽히게 하는 3중 방어

가. 초기 은닉을 `[data-js]` 아래에서만 적용한다.
나. 첫 페인트 전 인라인 스크립트가 `data-js` 를 세운다.
다. `<noscript>` 스타일이 은닉을 덮어쓴다 — Motion 이 `initial` 을 서버 HTML 의 인라인
스타일로 내보내므로 가·나 만으로는 부족하다 (E2E 에서 확인됨).

미해결: JS 가 켜져 있는데 하이드레이션이 실패하는 경우는 덮지 못한다. 그 경우까지 막으려면
히어로를 CSS 소유로 옮겨야 하고, 그것은 소유권 변경이므로 이 문서를 먼저 고쳐야 한다.

## 11. 호버 · 포커스 거동

- 호버는 **대비만** 바꾼다. 위치 · 크기를 바꾸지 않는다.

  안에서만 — 터치 기기의 sticky hover 를 만들지 않는다.

### 12.2 게이트

`src/motion-ownership.test.ts` 가 소스 grep 으로 강제한다. 통과 중이며 확장 시 함께 고친다.

- 검사 대상 파일이 실제로 발견되는지 먼저 단정한다 (glob 이 0개를 돌려주면 모든 검사가

- `scroll-behavior` 금지 (`overscroll-behavior` 는 제외).
- **`<motion.` · `layout` · `initial={` 는 허용 목록 안에서만** —
  현재 `src/components/Hero`, `src/components/DirTree`. 파일이 늘면 §12 표와 함께 고친다.

주석은 검사 전에 걷어낸다. grep 은 사용과 언급을 구분하지 못하므로, 규칙을 추가할 때마다
같은 오탐을 다시 만들지 않기 위해서다.

## 13. 축소 모션 (`prefers-reduced-motion: reduce`)

| ID | 축소 모션에서 |
|---|---|
| SP1 | 척추가 이동하지 않고 **즉시 해당 절의 참값 위에 놓인다.** 위치 정보는 사라지지 않는다 |
| S2 | 자리 이동 없이 즉시 최종 배치. 토글은 계속 동작한다 (기능을 빼지 않는다) |
| H1 | 최종 상태 즉시 렌더. 초기 상태를 거치지 않는다 — **서버 HTML 단계에서** (§13.1) |
| G1 · L1 · SP2 | 유지한다 — 색과 두께만 바뀌고 아무것도 이동하지 않으므로 축소 대상이 아니다 |

축소 모션에서 **기능이 사라지지 않는다.** 사라지는 것은 이동뿐이다.

### 13.1 축소 모션은 하이드레이션을 기다리지 않는다

**신설 (2026-08-31, GOLDEN_FIX 1).** 접근성 감사가 계측한 결함:
`useReducedMotion()` 은 `matchMedia` 이므로 클라이언트에서만 해석된다. 그래서 서버가
축소 모션 사용자에게도 `initial={{opacity:0}}` 을 내보내고, 히어로는 하이드레이션까지
보이지 않는다 — 커밋 후 **192ms**, CPU 6x 스로틀에서 **1399ms**.

즉 축소 모션을 요청한 사용자가 정확히 **"애니메이션이 로드에 실패한 화면"** 을 본다.
이것은 §13 의 표를 위반하는 것이고, 축소 모션 대체가 설계된 것이 아니라 방치된 것이라는
증거다.

규칙:

- 축소 모션 분기는 **첫 페인트 전에** 결정되어야 한다. `data-js` 를 세우는 것과 같은
  방식으로 인라인 스크립트가 `prefers-reduced-motion` 을 읽어 루트에 속성을 세운다.
- 초기 은닉(`[data-enter] { opacity: 0 }`)은 **축소 모션이 아닐 때만** 적용한다.
- 서버 HTML 이 축소 모션 사용자에게 은닉 상태를 인코딩하지 않는다.
- 판정 방법: `reducedMotion: "reduce"` 로 로드해 커밋 직후 `opacity` 가 `1` 인지 본다.
  하이드레이션을 기다리는 구현은 이 검사를 통과할 수 없다.
