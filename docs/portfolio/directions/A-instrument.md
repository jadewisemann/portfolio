작성: ART_DIRECTION_BRANCH · 2026-08-31

  **색 교체는 방향의 차이로 인정하지 않는다.**
- 이미지 자산이 0장이다 (`CONTENT.md` §8). 세 방향 모두 사진 없이 성립해야 한다.

차이는 **구조**에서만 만든다.

## 1. 개념

사이트를 문서가 아니라 **계측기**로 만든다. 화면의 모든 요소는 눈금 · 하한 · 임계값 ·
편차 폭 중 하나다. 방문자는 글을 읽는 게 아니라 **계기판을 읽는다.**

근거: 이 포트폴리오의 소재 중 가장 강한 것이 측정 행위 자체다 —
같은 테스트를 2회 실행해 전역 branches 90.48% 와 91.43% 를 비교해 흔들리는 파일을
특정한 일(`CONTENT.md` §2.3). 그것은 서술이 아니라 계측이다.

## 2. 감정적 성격

차갑고 정확하다. 설득하지 않고 판독을 요구한다. 냉정함이 신뢰로 읽히는 쪽에 건다.

## 3. 시각 은유

교정 성적서(calibration certificate). 실험실 장비에 붙어 나오는 종이 —
측정값, 허용 오차, 측정 조건, 서명이 한 장에 있는 그 형식.

## 4. 타이포그래피

- **등폭이 본문이다.** IBM Plex Mono 가 지면의 60% 이상을 차지한다. Sans 는 설명 문단에만.
- 숫자는 `tnum` 고정. 소수점이 세로로 정렬되는 것이 이 방향의 미학 전부다.
- 계측값 활자 계단: 13 / 14 / 22 / 48 / 96px. 48 이상은 **측정값에만** 허용한다 —
  제목에 큰 활자를 쓰지 않는다. 지면에서 가장 큰 글자는 항상 숫자다.
- 제목은 작다 (17px 대문자 트래킹). 계기판의 라벨처럼.

## 5. 그리드

가짜 장식 그리드가 아니라 **좌표계**다.

- 가로: 12열이 아니라 **백분율 축**. 0% 에서 100% 까지의 실제 스케일이고, 모든
  측정 막대가 같은 축을 공유한다. 서로 다른 절의 막대를 눈으로 겹쳐 비교할 수 있다.
- 세로: 28px 리듬 유지. 눈금선은 라벨이 붙은 것만 그린다 (0 · 50 · 90 · 96 · 100).
- 왼쪽 여백에 축 라벨 열(56px) 고정.

## 6. 내비게이션

좌측 계기 인덱스. 각 절이 "무엇을 재는가"로 나열되고, 현재 판독 중인 항목이 표시된다.
기존 `Gutter.tsx` 의 레일을 계측 항목 목록으로 재사용한다.

## 7. 프로젝트 서술

프로젝트마다 **판독표 하나**를 만든다. 형식이 고정된다:

```
측정 대상   YORR 프론트엔드 커버리지
분모        src/**/*.{ts,tsx} 전체 (테스트가 import 한 파일이 아니라)
측정        96.33 / 91.94 / 96.63 / 98.40
하한        96 / 91 / 96 / 98
조건        vitest 4 + v8, 로컬. CI 는 커버리지를 끈 npm test 를 돌린다
등급        A — frontend/vitest.config.ts 주석
```

세 프로젝트가 같은 서식을 쓰므로 비교가 가능하다. 서사는 문장이 아니라 표의 차이에서 나온다.

## 8. 이미지 처리

사진 0장. 이미지 자리에는 **측정 그래프**가 들어간다. SVG 로 직접 그리며 라이브러리를
쓰지 않는다 (데이터 점이 8개 이하이므로 차트 라이브러리는 순수 손실).

## 9. 깊이 모델

깊이 없음. 완전 평면. 그림자 0, 블러 0. 레이어는 잉크의 농도(ink / ink-2 / ink-3)로만
표현한다. 계측기 인쇄물에는 z축이 없다.

## 10. 배경 시스템

기존 28px 괘선 기판을 유지하되 **의미를 바꾼다**: 장식이 아니라 좌표 격자로 라벨을 붙인다.
`position: fixed` 유지 (스크롤 중 리페인트 없음).

## 11. 스크롤 철학

절 단위 정독. 스크롤은 이송(transport)일 뿐이며 아무것도 구동하지 않는다.
스크롤 위치의 함수인 속성은 0개다. 스크롤 스크럽 · 패럴랙스 · 핀 없음.

## 12. 시그니처 인터랙션

1. **축 공유 비교** — 서로 다른 절의 측정 막대가 같은 백분율 축에 놓여, 페이지를 훑으면
   하한 눈금들의 높이 차이가 주변시에 남는다. 인터랙션이 아니라 정보 설계다.
2. **호버 시 조건 노출** — 측정값에 포커스하면 측정 조건(명령 · 시점 · 분모)이 인라인으로
   펼쳐진다. CSS 소유, 120ms, 위치 이동 없음.

## 13. 컴포넌트 후보

- B1 `MeasurementBar` (이미 구현) — 이 방향의 주역.
- 신규: `AxisFrame` (라벨 붙은 백분율 좌표계), `ReadoutTable` (판독표 서식).
- 반려된 기성품 전부 그대로 반려 (`COMPONENT_REGISTRY.md` §2).

## 14. 모바일 전략

320px 에서 백분율 축을 유지하되 축 라벨을 막대 위로 올린다. 판독표는 2열 정의 목록으로
접힌다. **측정값의 활자 크기를 줄이지 않는다** — 이 방향에서 숫자는 이미지이므로
줄이면 방향이 사라진다. 대신 라벨을 줄인다.

## 15. 성능 위험

거의 없음. SVG 정적, JS 거의 없음, 이미지 0. 유일한 위험은 등폭 한글 폴백
(`globals.css` 주석의 미해결 사항).

## 17. 이 방향의 치명적 약점

**GOLDEN_REVIEW 의 시각 충격 임계값 9 를 넘지 못한다.** 계기판은 정보 밀도로
승부하는 형식이고, 밀도는 충격과 다르다. 큰 숫자 하나로는 9 를 만들지 못한다 —
