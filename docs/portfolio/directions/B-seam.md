# Direction B — 이음선 (Seam)

작성: ART_DIRECTION_BRANCH · 2026-08-31

공통 전제는 `A-instrument.md` §공통 전제 와 같다 (팔레트 · 서체 · 리듬 · 이미지 0장 ·
모션 게이트 고정). 차이는 구조에서만 만든다.

---

## 1. 개념

**이 포트폴리오의 모든 사실은 두 상태의 차이로만 존재한다.** 그것을 발견하고 나면
레이아웃이 결정된다.

| 사실 | 상태 A | 상태 B |
|---|---|---|
| 구조 재편 236파일 | 레이어 우선 | 도메인 우선 |
| 커버리지 흔들림 | 실행 1 (branches 90.48%) | 실행 2 (91.43%) |
| E2E 두 벌 | MSW — 소스 검증 | Playwright 페이크 — 빌드 산출물 검증 |
| 역할 경계 | 내가 한 일 | **내가 하지 않은 일** |
| 롤백 | 404파일 리팩터링 | 되돌린 상태 |
| 팀 구성 | FE 5명 중 1명 (FestiFriends) | FE 1명 (YORR) |
| 커밋 | 비-머지 81 | 통합 머지 103 |
| Firestore 규칙 | `read: if true` | `write: if false` |
| FSM | `PROCESSING` | (재진입 없음) |

그래서 지면의 유일한 구조 장치는 **이음선(seam)** 하나다. 화면을 좌/우로 가르는 수직
경계선이며, 사이트 전체를 관통한다. 왼쪽이 상태 A, 오른쪽이 상태 B, 선이 그 경계다.

## 2. 이음선이 정보를 나른다 — 이 방향의 핵심

**이음선의 위치가 그 절의 수치다.** 장식이 아니라 값이다.

- 커밋 81 : 103 → 이음선이 화면 폭의 **44%** 지점.
- 테스트 파일 20 / 팀 60 → **33%**.
- E2E mock 14 : real 4 → **78%**.
- 단독 작성 `functions/src` 10/10 → **100%** — 이음선이 오른쪽 끝에 붙어 사라진다.
  이 절만 화면이 한 덩어리다. 단독 작성이라는 사실이 레이아웃으로 증명된다.
- 관여 0건 (실시간 채팅) → **0%** — 이음선이 왼쪽 끝에 붙고 왼쪽 칸이 사라진다.
  "내가 한 일"이 물리적으로 0폭이 된다.

숫자를 읽지 않아도 비율이 눈에 들어온다. 10초 독자를 위한 장치이고, 동시에 숫자를 분모에서
떼어낼 수 없게 만드는 장치다 — **비율이 곧 레이아웃이므로 분모 없는 수치는 그릴 수 없다.**

## 3. 감정적 성격

긴장. 두 칸의 폭이 절마다 달라지므로 지면이 계속 기울어지고, 정직함이 미학이 된다.
편안하지 않다. 편안함을 목표로 하지 않는다.

## 4. 시각 은유

접힌 종이의 접선, 그리고 diff 뷰의 중앙선. 둘 다 "여기가 경계다"만 말하고 어느 쪽이
옳은지는 말하지 않는다.

## 5. 타이포그래피

- 두 칸의 활자는 **같은 급수 · 같은 무게**다. 한쪽을 크게 하면 방향이 무너진다 —
  "하지 않은 일"을 작게 조판하는 순간 그것은 각주가 되고, 각주는 아무도 읽지 않는다.
- 이음선 위에 그 절의 비율을 등폭으로 얹는다: `81 : 103`. 이것이 지면에서 가장 큰
  글자다 (56px / 320px 에서 32px). **큰 활자는 비율에만 허용한다.**
- 본문 17px Sans, 측정값 · 경로 · 명령 14px Mono. 기존 계단을 유지한다.
- 한글 조판 규칙 유지: `word-break: keep-all`, `:lang(ko)` 행간 1.7.

## 6. 그리드

- 12열 그리드를 쓰지 않는다. 열은 항상 **정확히 둘**이고, 그 폭 비율이 데이터다.
- 이음선의 최소 폭 보호: 어느 칸도 12% 미만이 되지 않는다 — 다만 **0% 와 100% 는
  예외로 허용한다** (관여 0건 · 단독 작성 100%). 4% 같은 어중간한 값은 12% 로 올리고
  실제 비율을 이음선 라벨에 적는다. 레이아웃이 거짓말하지 않도록 라벨이 정본이다.
- 수직 리듬 28px 유지. 이음선은 정수 픽셀 위치.

## 7. 내비게이션

이음선 자체가 내비게이션이다. 좌측 거터 레일(기존 `Gutter.tsx`)은 유지하되 역할을 줄여
**판단 기호 목록**만 담고, 위치 감각은 이음선의 기울기 변화가 준다.

## 8. 프로젝트 서술

프로젝트마다 이음선이 3~4번 위치를 바꾼다. 절 하나 = 비교 하나 = 이음선 위치 하나.
YORR 는 이음선이 가장 많이 움직이는 블록이고(1순위이므로), Pookjayo 는 2번만 움직인다.

## 9. 이미지 처리

사진 0장. 이음선의 위치 변화가 이 사이트의 유일한 이미지다.
스크린샷이 없다는 제약이 오히려 방향의 근거가 된다 — **보여줄 화면이 없으므로
구조를 보여준다.**

## 10. 깊이 모델

깊이 대신 **두께**. 이음선은 1px / 2px 두 종류이고, 2px 는 그 경계가 되돌릴 수 없는
것일 때만 쓴다 (롤백 · 관여 0건). 그림자 · 블러 없음.

## 11. 배경 시스템

기존 28px 괘선 기판 유지. 추가로 이음선 뒤에만 `--ground-sub` 면을 깔아 두 칸이 서로
다른 종이 위에 있게 만든다. 대비는 매우 낮게 (라이트 3%, 다크 4%) — 면이 보이는 게
목적이 아니고 경계가 우연이 아님을 알리는 게 목적이다.

## 12. 스크롤 철학

스크롤은 이송뿐. 스크롤 위치의 함수인 속성은 0개.
**이음선은 스크롤에 따라 움직이지 않는다** — 절마다 고정 위치이고, 절이 바뀌면 값이
바뀌는 것이다. 스크럽으로 만들면 "값"이 "연출"로 강등된다.

## 13. 시그니처 인터랙션

1. **구조 재편 트리 (S-restructure)** — 레이어 우선 트리(왼쪽)와 도메인 우선 트리(오른쪽)가
   같은 236개 노드를 공유하고, 사용자가 토글하면 노드가 **같은 아이덴티티를 유지한 채**
   자리를 옮긴다. Motion `layout` 소유, 320ms, `--ease-sort`. 파일이 사라지고 나타나는 게
   아니라 **이동한다**는 것이 사실과 일치한다 (커밋 `91b3363` 은 이동이다).
   기성품에 이 전이가 없어서 직접 만든다 (`COMPONENT_REGISTRY.md` C1 · B3).
2. **이음선 라벨 포커스** — 이음선 라벨에 포커스하면 그 비율의 분모 · 근거 경로 · 등급이
   펼쳐진다. CSS 소유, 120ms.
3. 히어로 두 줄 진입 (기존 `Hero.tsx`, Motion 소유, 1회).

애니메이션 소유자는 셋뿐이고 서로 겹치지 않는다: Motion(히어로 · 트리), CSS(상태 · 대비),
IntersectionObserver(불리언만, 보간은 CSS).

## 15. 모바일 전략

이음선이 **수평선**이 된다. 상태 A 가 위, B 가 아래이고, **선의 세로 위치가 같은 비율을
표현한다** (블록 높이 비율). 비율 라벨은 선 위에 남는다.
320px 에서 두 칸을 좌우로 두는 시도를 하지 않는다 — 그게 이 방향이 좁은 폭에서 죽는
가장 흔한 방식이다. 회전이 아니라 **축 교체**다.

## 16. 성능 위험

- 트리 전이가 유일한 위험. 236개 노드를 전부 DOM 에 두면 layout 애니메이션이 무너진다.
  → **표시는 도메인×레이어 칸 31개로 줄이고 나머지는 수치로 적는다** ("나머지 212파일").
  줄인 사실을 화면에 밝힌다 — 조용히 자르지 않는다.
- 그 외 위험 없음. 이미지 0, 라이브러리 추가 0~1.

## 18. 이 방향의 약점 (숨기지 않는다)

- **반복 피로**: 장치가 하나뿐이므로 절이 12개를 넘으면 지루해진다.
  → 완화: 0% 와 100% 절(관여 0건 · 단독 작성)을 리듬의 파열로 배치한다.
- **두 칸의 길이 불균형**: 왼쪽 텍스트가 짧고 오른쪽이 길면 빈 칸이 생긴다.
  → 완화: 짧은 쪽에 근거 경로 · 등급 · 명령을 넣는다. 채울 것이 항상 있다.
- 모바일에서 높이 비율이 콘텐츠 길이에 종속된다. 최소 높이를 두고 라벨을 정본으로 삼는다.
