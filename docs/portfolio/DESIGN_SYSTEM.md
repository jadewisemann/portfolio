# Design System

확정: 2026-08-31 · DESIGN_SYSTEM 노드 · 아트 디렉션: `ART_DIRECTION.md` (이음선)

## 1. 값의 정본과 구현

이 문서가 **값의 정본**이고, 구현은 `src/app/globals.css` 의 `:root` · `@theme inline` 이다.
둘이 어긋나면 이 문서를 먼저 고치고 CSS 를 맞춘다. 대비 수치는 WCAG 상대 휘도로 계산한 값이다.

라이트가 정본이다. 다크는 라이트의 반전이 아니라 **두 번째 문서 상태**로 따로 설계한다.

## 2. 면과 그림자

- 면은 두 개뿐이다: `--ground`(종이)와 `--ground-sub`(하위 면).
- `--ground-sub` 의 용도는 두 곳으로 제한한다: 이음선 오른쪽 칸, 그리고 코드 블록.
- **`box-shadow` 의 유일한 허용 형태는 `inset` 이다.** 바깥으로 나가는 그림자 · 글로우 ·
  `filter: blur` · `backdrop-filter` 는 전부 금지다. 이 규칙은
  `src/motion-ownership.test.ts` 가 소스 grep 으로 강제한다.
- 깊이는 z축이 아니라 잉크 농도와 선 두께로 표현한다 (`ART_DIRECTION.md` §3.13).
- 둥근 모서리는 코드 블록에만, 2px 까지.

규칙:

- 본문 대비 하한 7.0, 주석 하한 4.5 (AA 초과 목표). 위 값은 전부 만족한다.
- **신호색을 텍스트 색으로 쓰지 않는다.** 눈금 · 표시선에만 쓴다.
- **색만으로 구별되는 상태를 만들지 않는다.** 기호 · 위치 · 라벨이 항상 함께 있어야 한다.
- 괘선 세기는 테마별로 다르다: 라이트 `--rule-strength: 55%`, 다크 `24%`
  (`ART_DIRECTION.md` §3.10).
- **괘선 기판 대비 하한 1.6:1 (개정 2026-08-31, GOLDEN_FIX 1).** 실측된 결함:
  28px 괘선 기판이 라이트에서 `#eae7e3` on `#faf9f6` = **1.18:1** 로 사실상 보이지 않았다.
  `ART_DIRECTION.md` §3.11 은 이 기판에 "수직 리듬이 실재한다는 증거"라는 역할을
  걸어 두었는데, 보이지 않는 증거는 증거가 아니다. 라이트에서 1.6~1.8:1 로 올린다.
  모바일 3px 척추도 같은 문제였다 (`#dddad3` on `#faf9f6` = 1.31:1).
- **`--ground-sub` 의 문서와 구현이 어긋났다.** §2 는 용도를 "이음선 오른쪽 칸,
  코드 블록"으로 적었으나 실제로는 `CodeBlock` 과 DirTree 눌림 상태에만 배선되어 있고
  `.seam-col-b` 의 배경은 투명이었다. 오른쪽 칸에 실제로 적용하거나 §2 에서 그 용도를
  삭제한다 — 둘 중 하나를 고르고 문서와 코드를 일치시킨다.

## 4. 활자

서체는 IBM Plex 한 가족이다: Sans KR (400 · 600) 와 Mono (400). 로컬 서브셋
(`src/fonts/`, `npm run fonts` 로 생성). `next/font/google` 은 korean 서브셋 지원 서체가
0종이므로 쓰지 않는다.

### 등폭 스택 규칙

`--font-mono` 는 `Plex Mono → Plex Sans KR → ui-monospace` 순이다. Sans KR 을 이어 붙이지
않으면 등폭으로 조판된 모든 한글이 OS 대체 글꼴로 떨어진다 (CDP `getPlatformFontsForNode`
로 확인된 결함). 대가: 한글은 등폭이 아니므로 그 줄의 격자 정렬이 깨진다.

**미해결 판단**: 등폭을 라틴 · 숫자 · 경로 · 기호로 좁히는 것이 더 정직한 대안이다.
GOLDEN_FIX 에서 판정한다.

### 급수

| 토큰 | 값 | 쓰임 |
|---|---|---|
| — | 17px | 본문 (Sans) |
| `--text-mark` | 14px | 기호 · 라벨 |
| `--text-mono` | 14px | 측정값 · 경로 · 명령 |
| `--text-note` | 13px | 주석 · 분모 |
| `--text-rail` | 22px / `--leading-rail` 28px | 거터 레일 기호 |
| `--text-decision` | 28px | 판단 제목 |
| `--text-ratio` | 40 / 96 / **176px** | **이음선 비율 라벨** |
| `--text-display` | 26 / 30 / 56 / **72px** | 히어로 두 줄 |

**개정 (2026-08-31, GOLDEN_FIX 1) — 계단의 상단이 비어 있었다.**

실측된 결함: 히어로 `h1` 이 **1440 과 1920 에서 동일하게 36px / 544px 측정폭**이었다.
데스크톱 오프닝에 존재감이 없고, 1920 첫 뷰포트의 58.3% 에 잉크가 0이었다. 원인은
급수 계단이 **320px 실측에서만 파생**되어 데스크톱 레지스터가 아예 없었던 것이다.
동시에 구현은 `--text-ratio` 를 문서에 없는 96px 로 출하했다 (문서 값 56px).

- **디스플레이 레지스터를 신설한다.** 히어로는 ≥1024px 에서 72px 까지 올라간다.
- **지면에서 가장 큰 글자는 여전히 항상 비율이다.** 그래서 비율 라벨을 176px 로 함께
  올린다. 이 위계가 깨지면 방향이 무너진다 (`directions/B-seam.md` §5).
- 176px 은 **0% · 100% 절의 전폭 슬롯에서만** 성립한다. 12% 칸에 176px 을 넣지 않는다 —
  급수는 척추의 높이와 칸의 폭에서 파생되고, 두 값이 허용하는 상한을 넘지 않는다.
- **`clamp()` 를 쓰지 않는다** — 32px 과 30px 사이에 6줄에서 4줄로 뛰는 불연속이 있어
  연속 보간은 60vh 상한을 깨는 구간을 반드시 통과한다. 이산 브레이크포인트 계단을 쓴다.
- 히어로 4단계는 실측으로 다시 정한다: 26(320) / 30(640) / 56(768) / 72(1024).
  각 단계에서 히어로 높이 ≤ 60vh 와 첫 뷰포트 안 완전 수용을 기하로 재검증한다.
- 숫자는 `font-feature-settings: "tnum"` 고정 (등폭 · 코드 · pre).
- 한글 조판: `word-break: keep-all` + `overflow-wrap: break-word`,
  행간 `:lang(ko)` 1.7 / `:lang(en)` 1.6.

## 5. 레이아웃과 넘침

- 수직 리듬 **28px**. 모든 세로 간격은 그 배수다. 배경 괘선이 이 리듬의 증거다.
- 본문 측정폭 `--spacing-measure` 34rem. 거터 `--spacing-gutter` 4.5rem.
- 앵커 착지: `[id] { scroll-margin-top: 56px }` (28px × 2). `scroll-behavior` 는 쓰지 않는다.
- **넓은 산출물은 자기 컨테이너 안에서만 가로 스크롤한다** — `.scroll-x` 에
  `overflow-x: auto` + `overscroll-behavior-x: contain`. 본문(`documentElement`)은
  절대 가로로 스크롤되지 않으며, `e2e/geometry.spec.ts` 가 기하로 판정한다.

## 6. 이음선 토큰 (신규)

| 토큰 | 값 | 의미 |
|---|---|---|
| `--seam-min` | `12%` | 칸의 최소 폭. 0% · 100% 는 예외 |
| `--seam-weight` | `1px` | 기본 두께 |
| `--seam-weight-hard` | `2px` | 되돌릴 수 없는 경계 (롤백 · 관여 0건) |
| `--seam-gap` | `28px` | 두 칸 사이 여백 (리듬의 1배수) |

규칙:

- 이음선 위치는 **정수 픽셀**로 계산한다. 백분율을 그대로 CSS 에 넘기면 소수점 좌표가
  생겨 1px 선이 두 픽셀에 걸쳐 번진다. 컨테이너 폭에서 반올림한다.
- 비율 라벨이 정본이고 폭은 근사다 (`ART_DIRECTION.md` §3.4).
- 두 칸의 활자 급수 · 무게는 같다. 한쪽을 축소하는 유틸리티를 만들지 않는다.

## 7. 접근성 요구 (게이트 대상)

- **스킵 링크가 첫 포커스 가능 요소다.** 포커스를 받을 때만 보인다.
  `e2e/geometry.spec.ts` 가 Tab 한 번으로 검증한다.
- 포커스 링: `outline: 2px solid var(--ink)` + `outline-offset: 2px`.
  `:focus-visible` 만 쓰고 `outline: none` 을 어디에도 쓰지 않는다.
- 링크는 평상시 밑줄 1px, hover/focus 에서 2px. **색만으로 링크를 표시하지 않는다.**
  이 규칙은 `@layer base` 안에 두어야 한다 — 레이어 밖에 두면 Tailwind 의
  `.no-underline` 유틸리티를 이겨서 기호 칸까지 밑줄이 칠해지고, `−`(막았다)가 2획이 되어
  `=`(확인했다)로 오독된다 (6배 확대로 발견된 결함).
- 기호 글리프는 `aria-hidden`, 접근 가능한 이름은 `sr-only` 텍스트가 만든다.
- 터치 목표 최소 44×44px. **예외는 없다** (거터 레일은 §3.7 로 삭제되었다).
  실측된 결함 (2026-08-31): `EvidenceNote` 의 근거 링크가 320px 에서 **215.8×17px** 로
  하한의 39% 이며 WCAG 2.2 AA 의 24×24 도 미달이었다. 이 컴포넌트는 모든 절에 반복되므로
  확장 시 사이트 전체로 복제된다. **활자 급수(13px)를 키우지 않고 히트 영역만** 44px 로
  만든다 (`.tree-toggle button` 이 이미 쓰는 패턴).
- **포커스 링은 전이하지 않는다.** `transition-colors` 는 `outline-color` 를 포함하므로
  포커스 링에 쓰지 않는다 — 실측 결과 포커스 링이 120ms 간 `--ink-3` 에서 `--ink` 로
  전이했다 (`MOTION_LANGUAGE.md` §11 위반). 전이 속성을 `color` 로 명시한다.
- 축소 모션에서 위치가 변하는 모든 전이는 최종 상태를 즉시 렌더한다
  (상세는 `MOTION_LANGUAGE.md`).

## 8. 반응형

브레이크포인트는 세 개뿐이다.

| 폭 | 이음선 | 거터 레일 | 비율 라벨 |
|---|---|---|---|
| `< 768px` | 수평선 (축 교체) | 만들지 않는다 | 32px |
| `≥ 768px` | 수직선 | sticky 표시 | 48px |
| `≥ 1024px` | 수직선 | sticky 표시 | 56px |

- 320px 이 하한이다. 그 폭에서 넘침 0건을 기하로 판정한다.
- 모바일에서 두 칸을 좌우로 두려는 시도를 하지 않는다.

## 9. 금지 (기계 검사됨)

`src/motion-ownership.test.ts` 가 소스에서 잡는 것: `transition-all` · `will-change` ·
`@keyframes` / `animation:` · `filter: blur` / `backdrop-filter` · inset 아닌 `box-shadow` ·
`scroll-behavior` · `gsap` / `lenis` import · `useScroll` / `useTransform` / `scrollYProgress`.

이 게이트를 후보 컴포넌트나 편의를 위해 느슨하게 만들지 않는다 —
이 사이트의 포지셔닝 둘째 문장이 그 게이트의 존재로 증명된다.
